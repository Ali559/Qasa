Phase 7: the site's own icon

A login saved from a website or app shows that site's icon. The hard-coded logos go. When there's no icon or it can't be fetched, the tile falls back to one of the options below. The icons here are stand-ins (each brand's mark in its colour) so the page needs no network.

1. The fallback

Google, Facebook, Instagram and GitHub have an icon here; FIB, Asiacell and Korek don't (no favicon, or it couldn't be reached). Notes and cards keep their type icon.

2. Where the icons come from

This is the privacy decision. Today nothing is fetched, on purpose: the bundled-logo README says fetching favicons "would tell a third party which sites the user has". Whatever is picked, an icon is fetched once when the login is saved, kept with the item (encrypted, synced), and never fetched again on other devices.

Recommended

A · Straight from the site

  • The app asks the login's own site for its icon (/favicon.ico, or the icon its page links to).
  • Only that site sees the request, and you already use it. No third party, no Qasa server.
  • Some sites block it or have no icon: those get the fallback.
  • On Android, an app's icon comes from the phone itself (no network at all).
Middle

B · Through a Qasa icon server

  • The apps ask a Qasa server, which fetches and caches icons (as 1Password and Bitwarden do).
  • More reliable and uniform sizes, but Qasa's server sees which sites a user saves, even if it keeps no logs. That cuts against "Only you can see your passwords".
  • A server to run and pay for.
Not recommended

C · A public favicon service

  • Google's or DuckDuckGo's favicon API.
  • Easiest, but every saved site goes to Google or DuckDuckGo with the user's IP address.
